# garden-calendar-ai-server
# AI Ботаник — AI-сервер

Backend-сервер для Android-приложения **«AI Ботаник»** (RuStore).  
Принимает запросы от мобильного клиента, обрабатывает их через AI-провайдеров (DeepSeek, AITUNNEL) и возвращает структурированные ответы.

---

## О проекте

**AI Ботаник** — приложение для садоводов, огородников и любителей комнатных растений.  
Сочетает планировщик садовых работ, AI-агронома и определитель болезней растений по фото.

Сервер отвечает за:
- Текстовые AI-запросы (уход, вредители, болезни, справочник).
- Анализ фотографий растений (vision).
- Генерацию годовых планов задач по культурам.
- Учёт дневных лимитов запросов.
- Кэширование ответов (текст и планы).
- Фильтрацию несадоводческих запросов.
- Мониторинг состояния upstream-провайдеров.
- Админ-панель со статистикой.

**Клиент:** Android-приложение на Kotlin + Jetpack Compose.
Версия **2.0 «Модель данных v2»** (versionCode 3, 06.10.2026): Room v9
(локации/теги/посевы/урожаи/фото/каталог видов), добавление растения
по фото через `/api/identify`, карточка-питомец, история, архив,
интерфейс без эмодзи (векторные иконки). 1.1 отправлена на модерацию
RuStore 06.10.2026.

## AI-провайдеры

### DeepSeek — текстовые запросы

- **Base URL:** `https://api.deepseek.com`
- **Модели:** `deepseek-flash` (для `/api/ask` и `/api/generate-plan`).
- **Thinking mode:** отключён принудительно (`thinking={"type": "disabled"}`).
- **Используется для:** ответы про уход/вредителей/болезни, справочник, генерация планов, LLM-классификатор.

### AITUNNEL — анализ фотографий

- **Base URL:** `https://api.aitunnel.ru/v1`
- **Модели (каскадный фолбэк):**
  1. `gemini-2.5-flash` — основная, точная и недорогая.
  2. `gpt-4o` — резерв 1.
  3. `claude-sonnet-4.6` — резерв 2.
  4. `deepseek-v4-flash-vision-exp` — резерв 3, экономичная.
- **Используется для:** анализа фото растений.

Сервер по очереди пробует модели из списка. Если модель отвечает `200 OK` — ответ возвращается клиенту, остальные не трогаются. При ошибке (`429`, `404`, `402`) — переход к следующей.

## Эндпоинты

### Публичные

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/` | Health check. |
| `GET` | `/app/` | Веб-версия (PWA) «AI Ботаник» — статика из `static/`. |
| `GET` | `/privacy` | Политика конфиденциальности (зеркало `static/privacy.html`; основной домен частично недоступен из РФ). |
| `GET` | `/api/usage` | Текущий счётчик лимита для устройства. |
| `POST` | `/api/ask` | Текстовый AI-запрос. |
| `POST` | `/api/ask-photo` | Анализ фото растения. |
| `POST` | `/api/identify` | Определение вида по фото: кандидаты (группа 01–05, speciesKey, confidence) — для photo-first ввода в PWA. |
| `POST` | `/api/generate-plan` | Генерация годового плана задач. |

### Админские (требуют `X-Admin-Token`)

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/admin/stats` | Полная статистика сервера. |
| `GET` | `/api/admin/health` | Состояние upstream-провайдеров. |

## Переменные окружения

Настраиваются в Render → Environment:

| Переменная | Обязательно | Описание |
|---|---|---|
| `DEEPSEEK_API_KEY` | ✅ | Ключ DeepSeek для текстовых запросов. |
| `AITUNNEL_API_KEY` | ✅ | Ключ AITUNNEL для анализа фото. |
| `ADMIN_TOKEN` | ⚠️ | Токен для доступа к админ-эндпоинтам. Если не задан — админка отключена. |

**Локально** можно прописать в `.env` (не коммитится в git) или экспортировать через shell.

## Веб-версия (PWA)

PWA-клиент лежит в `static/` и раздаётся на **`/app/`**:
https://garden-calendar-ai-server.onrender.com/app/

Рабочая копия исходников: `Desktop/GardenCalendar/pwa/` (в репо
копируется при деплое). Функционально повторяет Android-версию и на
сейчас опережает её: модель данных v2 (группы 01–05, каталог 85 видов,
локации, теги, посевы/урожаи, фото-дневник, клички растений),
photo-first ввод через `/api/identify`, самочувствие/стрики/
достижения (клиентская логика, без AI-запросов). Данные — IndexedDB
(«ai-botanik», схема v2), только на устройстве.

Служит для тестирования на iPhone (Safari → «На экран “Домой”»).

### Деплой PWA

1. Заменить файлы в `static/` (из рабочей копии `pwa/`).
2. **Поднять версию кэша в `sw.js`** (`ai-botanik-vNN`; текущая — v21).
   Без подъёма версии клиенты остаются на старых файлах.
3. `git push` → Render пересобирается (1–3 мин).

Деплой на Render
Изменения пушатся в main ветку GitHub.

Render автоматически пересобирает сервис.

Время сборки: 1–3 минуты.

Проверка: GET / должен вернуть {"status":"ok","service":"ai-botanik"}.

Особенности бесплатного тарифа:

Сервис «засыпает» через 15 минут без запросов.

Первый запрос после сна занимает 30–60 секунд.

Решение: UptimeRobot с пингом каждые 5 минут.

Логика работы
Обработка текстового запроса (/api/ask)
Проверка правилами (rule_filter) — стоп-слова, маркеры садоводства.

LLM-классификатор (classify_topic) — для спорных запросов.

Проверка кэша — если ответ уже есть, вернуть из кэша (лимит не тратится).

Проверка лимита — increment_daily_usage (10 запросов в день на устройство).

Выбор промпта — обычный (care / pests / diseases / free) или indoor для комнатных.

Запрос к DeepSeek — с параметрами thinking=disabled, max_tokens=8000.

Сохранение в кэш — для повторных запросов.

Анализ фото (/api/ask-photo)
Проверка лимита — списывается 1 запрос.

Формирование запроса — изображение в base64 + системный промпт.

Каскадный вызов AITUNNEL — перебор моделей до успеха.

Возврат ответа с указанием использованной модели.

Генерация плана (/api/generate-plan)
Проверка кэша — ключ: культура + сорт + зона + фаза. TTL 90 дней.

Проверка лимита — если кэш промахнулся.

Запрос к DeepSeek с response_format={"type": "json_object"}.

Валидация JSON — проверка полей tasks, title, month, day.

Сохранение в кэш.

Особенности реализации
Кэш в памяти — при перезапуске сервера кэш теряется. Это нормально: пользовательский кэш на клиенте (Room) сохраняет ответы.

Лимиты в памяти — аналогично. При перезапуске счётчики обнуляются. Для MVP приемлемо.

Дневной лимит — 10 запросов на устройство. Учитывает часовой пояс пользователя.

Кэш hit не тратит лимит — важное поведение. Пользователь может повторять запрос без штрафа.

UTF-8 в ответах — принудительно, чтобы не было проблем с кириллицей.

CORS — открыт для всех (для Android не критично, оставлено для отладки).

Безопасность
API-ключи хранятся только в переменных окружения Render, не в коде.

Файл keystore.properties (для Android-подписи) — не в этом репозитории.

Админ-доступ защищён токеном X-Admin-Token.

Персональные данные пользователей не собираются: только анонимный ANDROID_ID.

Все данные хранятся локально на устройстве пользователя (Room).
